# /l-ref — 참고 자료 들이기

**목적:** 사람이 가진 자료를 어떤 형식이든 그대로 두고, AI가 필요한 절만 찾아 읽을 수 있게 색인한다.
원본은 고치지 않는다 (안의 자료에 제목을 더할 때만, 승인받고).

입력: `$ARGUMENTS` — `<종류> <경로>`. 종류는 `lantern.yaml`의 `references` 키와 같다.

| 종류 | 어떤 자료 | AI에게 가는 때 |
|---|---|---|
| `rules` | 사내 규칙 — 반드시 지킬 것, 짧다 | 늘 (AGENTS.md에 원문 그대로) |
| `terms` | 용어집 — 말의 뜻 · 쓰지 말 표현 | 한 줄 규칙만 늘, 표는 필요할 때 |
| `domain` | 도메인 지식 — 크고 많다, 가끔 필요하다 | 필요할 때만 (색인을 보고 그 절만) |

종류가 없으면 자료를 훑어보고 위 표로 추천한 뒤 확인받는다.

## 밖의 자료는 직접 열지 않는다
경로가 `~/…` · 절대 경로면 프로젝트 **밖**이다. 밖의 파일은 파일 읽기 도구로 열지 말고 `lantern ref check` · `lantern ref read "<문서>#<절>"`로만 읽는다.
어떤 AI 도구는 작업 폴더 밖을 읽을 때마다 허락을 묻고, 아무도 보지 않는 실행에서는 그대로 실패한다.
밖의 자료의 경로 · 제목 · 원문은 git에 올라가는 파일(문서 · 코드 · 커밋 메시지)에 옮겨 적지 않는다.

## 1. 받기
- 경로를 확인한다. PDF · HWP · Word는 Markdown(`.md`)으로 바꿔 **같은 폴더에** 두고 원본도 남긴다 (색인은 `.md`만 읽는다).
- 프로젝트 안에 둘지 밖에 둘지는 사람이 정한다. 공개하면 안 되는 자료는 밖에 둔다 — 밖의 자료는 경로도 색인도 git에 오르지 않는다 (`.lantern/references.yaml`).

## 2. 구조 보기
```bash
lantern ref check <경로>
```
- ⚠가 나오면 그 문서는 절 단위로 읽기 어렵다 (제목이 없음 · 제목 급을 건너뜀 · 너무 긴 절).
  - **안의 자료:** 내용은 그대로 두고 `##` 제목만 더하는 안을 보여 준다 → 승인받으면 더한다.
  - **밖의 자료:** 원본을 고치지 않는다. 무엇이 문제인지만 알리고, 사람이 원본을 고칠지 그대로 둘지 정한다.

## 3. 색인
```bash
lantern ref index <종류> <경로>
```
- 경로가 아직 목록에 없으면 더해진다: 안의 경로는 `lantern.yaml` `references.<종류>`(팀이 같이 씀), 밖의 경로는 `.lantern/references.yaml`(나만).
- 출력의 `+`는 새 절, `~`는 바뀐 절, `-`는 사라진 절이다. 다음 단계는 `+` · `~` 절만 다룬다 — 다시 들일 때 이미 승인한 절을 또 묻지 않는다.

## 4. 종류별로 정하기
이 폴더의 그 종류 파일만 읽고 따른다: `rules.md` · `terms.md` · `domain.md`.

## 5. 마무리
```bash
lantern close l-ref
```
