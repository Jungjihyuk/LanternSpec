# /l-ref rules — 적용 범위 · 강도 정하기

사내 규칙은 **승인한 절만** AI에게 간다. 절마다 두 가지를 제안하고 사람이 승인한다.

| 정할 것 | 값 | 뜻 |
|---|---|---|
| 적용 범위 `--scope` | `all` | 프로젝트 전체 → 루트 AGENTS.md |
| | 영역 폴더 (예: `backend`) | 그 영역에서만 → 그 영역의 AGENTS.md |
| | 언어 (예: `python`) | 그 언어의 코드에서만 → 그 언어를 쓰는 영역마다 |
| 강도 `--strength` | `must` | 반드시 지킴 — 공간이 모자라도 원문을 그대로 둔다 |
| | `should` | 되도록 따름 — 공간이 모자라면 제목과 읽는 명령만 남는다 |

영역이 둘 이상 정해지지 않았으면 범위와 상관없이 모두 루트 AGENTS.md로 간다. 고를 수 있는 범위는 틀린 값을 넣으면 오류 메시지에 나온다.

## 1. 제안하기
- 3번 출력의 `+` · `~` 절만 다룬다. 절은 `lantern ref read "<주소>"`로 읽는다 (밖의 자료도 같다).
- 절마다 한 줄로 제안한다: `주소 — 범위 · 강도 — 근거`.
  - 범위의 근거: 절이 말하는 대상 (예: "API 응답" → 서버 영역, "SQL" → 그 언어나 영역).
  - 강도의 근거: 원문의 말투 ("~한다 · 금지" → must, "권장 · 가능하면" → should). 애매하면 should.
- 규칙이 아닌 절(머리말 · 목차 · 개정 이력)은 승인 대상에서 빼고 "뺄 절"로 따로 보여 준다.
- 큰 절 아래 작은 절이 따로 범위가 다르면 작은 절마다 제안한다. 같으면 큰 절 하나로 묶는다.

## 2. 승인받고 저장하기
사람이 고친 대로 저장한다. 승인하지 않은 절은 저장하지 않는다.
```bash
lantern ref tag "<주소>" --scope <범위> --strength <must|should>
lantern ref tag "<주소>" --off          # 승인 거두기
lantern ref exclude "<주소>"            # 이 프로젝트에는 맞지 않는 절 — 승인해도 AI에게 가지 않는다
```
- `~` 절(바뀐 절)은 승인이 그대로 남아 있다. 바뀐 내용을 보여 주고 범위 · 강도를 그대로 둘지만 묻는다.
- `exclude`는 안의 자료면 `lantern.yaml`에(팀이 같이), 밖의 자료면 `.lantern/`에(나만) 남는다. 뺀 이유는 작업 기록에 한 줄 남긴다.

## 3. AGENTS.md에 넣기
```bash
lantern upgrade
```
- 안의 규칙은 원문 그대로 그 범위의 AGENTS.md "사내 규칙" 칸에 들어간다.
- 밖의 규칙은 AGENTS.md에 내용 없이 `lantern ref rules` 한 줄만 들어간다. 원문은 그 명령이 이 컴퓨터에서만 보여 준다.
  밖의 규칙을 처음 승인하면 `lantern.yaml`의 `references.outside_rules`가 `true`가 된다 (경로 · 제목 없이 "밖에 둔 사내 규칙이 있다"는 사실만). 팀원에게도 같은 줄이 보이고, 자료가 없는 팀원에게는 받는 법이 안내된다. 그만 따를 때는 사람이 `false`로 바꾼다.
- 예산을 넘었다는 ⚠가 나오면, should 규칙은 이미 제목만 남았다는 뜻이다. must 규칙이 너무 많은지 사람과 함께 본다.
