# /l-ref domain — 무엇 · 언제 읽나 정하기

도메인 지식은 **필요할 때만** 한 절씩 읽힌다. AI가 찾아가는 길은 색인(`lantern ref domain`) 하나다 — 절마다 네 가지를 제안하고 사람이 승인한다.
`<<folder.domain>>/`에 넣은 문서는 목록에 적지 않아도 된다. 그 밖의 경로만 3번 색인 때 목록에 더해진다.

| 정할 것 | 쓰는 법 |
|---|---|
| 무엇 `--what` | 그 절의 **주제만**. 규칙의 내용(숫자 · 기한 · 조건)은 쓰지 않는다 — 색인만 보고 아는 척하지 않게 |
| 언제 읽나 `--when` | 읽어야 하는 상황 (예: "회원 · 탈퇴 데이터를 저장 · 삭제하는 코드를 짤 때"). AI가 찾아가는 계기다 |
| 핵심 용어 `--keys` | 그 절을 찾게 하는 말 두세 개 |
| 원문 필수 `--verbatim` | 숫자 · 기한 · 예외 조항이 있는 절. 판단 직전에 원문을 다시 읽게 된다. 있으면 기본으로 제안한다 |

## 1. 제안하기
- 3번 출력의 `+` · `~` 절만 다룬다. 절은 `lantern ref read "<주소>"`로 읽는다 (밖의 자료도 같다).
- 절마다 한 줄로 제안한다: `주소 — 무엇 — 언제 읽나 — 핵심 용어 — 원문 필수 여부`.
- 하위 절이 짧으면 위 절 하나로 묶는다 (하위 절까지 함께 읽힌다). 머리말 · 목차 · 개정 이력은 빼고 "뺄 절"로 보여 준다.

## 2. 승인받고 저장하기
```bash
lantern ref describe "<주소>" --what "주제" --when "읽을 상황" [--keys "말, 말"] [--verbatim]
lantern ref describe "<주소>" --off          # 설명 거두기
lantern ref exclude "<주소>"                 # 이 프로젝트에서 뺄 절
lantern ref domain                            # 색인 보기
```
- 안의 자료는 `<<folder.domain>>/<<file.domain_moc>>`에도 보인다 (자동 생성 — 손으로 고치지 않는다). 밖의 자료의 설명은 이 컴퓨터의 `.lantern/`에만 남는다.
- 색인에 ⚠가 붙은 절은 설명한 뒤에 원문이 바뀐 것이다 — 다시 읽고 설명을 고친다.
- 읽기는 `/l-domain`과 `lantern ref read`가 한다. 작업에 거는 것은 `/l-plan`이 한다.
