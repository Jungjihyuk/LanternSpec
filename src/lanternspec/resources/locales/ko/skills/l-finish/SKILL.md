# /l-finish — 동시 작업 마무리

**목적:** worktree에서 끝난 작업들을 기준 브랜치에 하나씩 합치고, 모두 통과하면 현재 상태 문서를 한 번에 맞춘다.
여러 작업이 함께 쓰는 문서(현재 상태 · 보관 · 보고)는 이 스킬만 고치므로, **기준 폴더에서 세션 하나로만** 실행한다.

입력: `$ARGUMENTS` — 합칠 작업(`W-001 W-002`). 없으면 고르게 한다.
지금 설정: 현재 상태 반영 `<<build.merge_approval>>`<!-- lantern:if build.test --> · 테스트 `<<build.test>>`<!-- lantern:endif -->

## 0. 시작 전
- 합치기 전에는 각 작업의 실제 worktree에서 문서를 읽는다. 합치지 못한 이유는 마지막 대화 보고에만 적고, 기준 폴더의 해당 작업 문서에는 쓰지 않는다. 필요한 수정은 해당 worktree에서 진행한다.
- 기준 폴더에서 실행 중인지 확인한다. worktree 안이면 멈추고 기준 폴더에서 다시 실행하라고 알린다.
- `git status`에 커밋하지 않은 변경이 있으면 멈추고 알린다: "기준 폴더에 커밋하지 않은 변경이 있어요. 다른 마무리가 진행 중일 수 있어요."
- `lantern work list`로 "/l-finish 대기" 작업을 보여 주고, 이번에 합칠 것과 순서를 고르게 한다 (인자로 받았으면 그것만).

## 0½. 합치기 전 — 같은 역할을 다르게 만들었나
충돌 없이 합쳐지지만 같은 역할을 다르게 만든 곳은 git이 잡지 못한다. 합치기 전에 찾는다:
```bash
lantern work overlap W-001 W-002     # 실제로 함께 고친 파일 · 새로 더한 의존성 · 결정 기록
```
작업마다 `<<file.record>>`(결정 · 실패한 시도)와 `<<file.design>>`, 위 결과를 비교해 이런 곳을 찾는다:
인증 방식이 다름 · 같은 일을 하는 다른 라이브러리 · 같은 성격인데 모양이 다른 API · 같은 개념을 다른 테이블로 만듦.

찾았으면 그 작업들은 아직 합치지 않고 사람에게 보여 준다: **무엇이 다른가 · 어느 쪽을 추천하고 왜 · 선택지**
- **한쪽으로 맞추기:** 정해지면 `/l-adr`로 남긴다. 바꿔야 하는 작업은 합치지 않고 남기고, 마지막 보고에 "W-002 세션에서 ADR-NNN에 맞춰 고친 뒤 다시 `/l-finish`를 실행해 주세요"를 적는다. 코드는 이 스킬이 고치지 않는다.
- **둘 다 그대로 두기:** 이유를 `/l-adr`로 남기고 합친다.

겹치는 것이 없으면 바로 1절로 간다.

## 1. 하나씩 합치기 (고른 순서대로)
```bash
lantern work finish W-001     # 기준 브랜치 받기 → 테스트 → 합치기 → worktree 정리
```
- 충돌하면 `/l-build`의 **충돌이 나면** 절차대로 그 작업의 폴더(안내된 worktree)에서 처리하고 다시 실행한다. 자동 생성 문서만 충돌하면 명령이 알아서 처리한다.
- 테스트가 실패하면 그 작업은 합치지 않고 남겨 둔다. 다음 작업으로 넘어갈지 사람에게 묻는다.
- 세션이 worktree 폴더를 지울 수 없다고 하면 다른 방법으로 지우지 말고, 안내된 터미널 명령을 마지막 보고에 적는다.
<!-- lantern:endif -->

## 1. 하나씩 최신으로 맞추기 (고른 순서대로)
합치는 것은 PR이 한다. 작업마다 기준 브랜치를 받아 테스트한다:
```bash
lantern work finish W-001     # 기준 브랜치 받기 → 테스트 (머지는 하지 않는다)
```
- 충돌하면 `/l-build`의 **충돌이 나면** 절차대로 그 작업의 폴더에서 처리하고 다시 실행한다.
- 아래 2 · 3번은 **작업마다 그 작업의 폴더에서** 하고 그 브랜치에 커밋한 뒤, 사람에게 `/l-pr`을 안내한다.
<!-- lantern:endif -->

## 2. 현재 상태 반영 (합친 작업 모두)
- 작업마다 `<<file.design>>`과 `<<file.record>>`를 읽고, `/l-build`의 **모두 끝나면 — 현재 상태에 반영** 절차대로 요약 한 장씩을 보여 준다.
- 여러 작업이 같은 문서(예: `<<file.features>>`)를 고치면 한 장에 합쳐 보여 준다. 다른 작업이 적은 줄을 지우지 않는다.
- 승인 규칙은 `/l-build`와 같다. **데이터 구조 · API 변경은 값과 상관없이 묻는다.**

## 3. 보관 · 보고
`lantern work list`에 "합쳐짐"으로 남은 이번 작업의 브랜치가 있으면 `git branch -d <브랜치>`로 지운다 (worktree 정리가 중간에 멈추면 브랜치가 남는다). 지우지 못하면 마지막 보고에 명령을 적는다.
```bash
lantern work archive W-001    # 합친 작업마다
lantern close l-finish
lantern scan
lantern report
```
문서를 한 번에 커밋한다 (커밋 메시지에 합친 작업 ID를 모두 적는다).

## 4. 마지막 보고
합친 작업 · 남긴 작업과 이유 · 반영한 것 · `scan`에서 나온 어긋남 · `finish`가 낸 `⚠` · 사람이 터미널에서 지워야 하는 worktree.
