# /l-parallel — 동시 작업 시작 점검

**목적:** 여러 작업을 동시에 시작하기 전에, 함께 정해야 할 것을 먼저 정해 합칠 때 다시 고치는 일을 막는다.
작업마다 다른 방식으로 만들면(예: 한쪽은 JWT, 한쪽은 세션) 충돌 없이 합쳐져서 더 늦게 발견된다.

입력: `$ARGUMENTS` — 동시에 시작할 작업(`W-001 W-002`). 이미 실행 중인 worktree 작업도 함께 본다.

## 0. 준비
- 작업마다 `<<file.plan>>`와 `<<file.design>>`을 읽는다. 설계가 없는 작업은 "설계를 먼저 하면 점검이 정확해져요"라고 알리고, 기획만으로 계속할지 묻는다.
- 겹치는 곳과 연결된 결정 기록을 본다:
  ```bash
  lantern work overlap W-001 W-002     # 같은 파일 · 테이블, 작업마다 연결된 결정 기록
  ```
- `<<folder.decisions>>/`에서 이미 정한 결정(`<<adr_status.accepted>>`)을 읽는다. 이미 정한 것은 다시 묻지 않는다.

## 1. 함께 정할 것 찾기
두 작업 이상이 필요로 하는데, 설계에도 결정 기록에도 정해지지 않은 것을 찾는다:
- 인증 · 권한 방식 (예: JWT / 세션)
- 함께 쓰는 데이터 (같은 테이블, 서로 참조하는 테이블)
- API 형식 (응답 · 오류 모양, 주소 규칙)
- 공통 화면 부품 · 디자인 규칙
- 외부 서비스 · 큰 라이브러리

한 작업이 다른 작업의 결과에 기대는 경우도 찾는다 (예: 프로필은 로그인의 인증 방식에 기댄다).

## 2. 사람에게 정해 달라고 하기 (한 번에 하나씩)
항목마다 **무엇을 · 왜 함께 정해야 하나 · 추천과 이유 · 선택지**를 보여 준다. 추천은 네 판단이므로 이유를 꼭 적는다.

기대는 관계가 있으면 고르게 한다:
- 결정만 먼저 정하고 동시에 진행 (결정이 명확할 때 추천)
- 앞 작업을 먼저 끝내고 순서대로 진행

정해진 것은 `/l-adr`로 남긴다. 관련 작업마다 `<<file.design>>` frontmatter `adr`에 ID를 적고, 설계 글에도 반영한다. 고친 문서는 시작 전에 커밋한다 (worktree에는 커밋된 문서만 들어간다).

## 3. 시작
```bash
lantern work start W-001 W-002 --skip-check
```
- 함께 정할 것이 없었으면 "함께 정할 결정이 없어요"라고 알리고 바로 시작한다.
- 순서대로 하기로 한 작업은 지금 시작하지 않는다.
- 명령이 알려 준 실행 방법(터미널마다 한 줄)을 그대로 보여 준다.

## 공통 마무리
```bash
lantern close l-parallel
```
**다음:** 터미널마다 안내된 명령으로 `/l-build`를 실행한다. 모두 끝나면 기준 폴더에서 `/l-finish`.
